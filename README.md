# 백화점 마케팅 아침 점검 에이전트

출근 전에 혼자 돌아서, 마케팅 담당자가 아침에 확인할 것을 한 장으로 모아 줍니다. 판단은 정해진 규칙으로 하고, 모든 판단에 근거 숫자와 규칙 문장을 붙입니다.

- 시연 화면: https://jhheo51-arch.github.io/dept-morning-brief/
- 시연 화면의 매출, 행사, 시범, 현장 기록은 모두 가상 데이터입니다. 앱 리뷰와 날씨, 공휴일만 공개 자료입니다.

## 내 업무에 적용하기

회사 PC(Windows)에서 내 엑셀로 돌리는 방법입니다. 내 자료는 내 PC 안에서만 읽고 씁니다. Python을 설치할 수 없는 PC라면 아래 "Python 없이 쓰기(exe)"를 먼저 봅니다.

### 1. 설치

```bash
git clone https://github.com/jhheo51-arch/dept-morning-brief.git
```

```bash
cd dept-morning-brief
```

```bash
python -m venv .venv
```

```bash
.venv\Scripts\pip install -r requirements.txt
```

Python 3.11 이상이 필요합니다. 회사 PC에 설치가 막혀 있으면 IT 담당에 먼저 확인하거나 exe 판을 씁니다.

### Python 없이 쓰기(exe)

Python이 있는 PC에서 한 번 만들고, 만든 폴더를 회사 PC로 옮겨 씁니다.

```bash
scripts\build_exe.bat
```

`dist\morning_brief` 폴더가 생깁니다. 이 폴더를 통째로 회사 PC의 원하는 곳(예: `C:\work\morning_brief`)에 복사합니다. 폴더 안의 `run_brief.bat`를 두 번 누르면 처음에는 `inputs\` 양식과 `config.local.toml`을 만들고 멈춥니다. 엑셀을 채운 뒤 다시 누르면 `output\site\index.html`이 열립니다. 아래 3번부터는 같고, `run_brief.bat`도 이 폴더의 것을 씁니다.

- 회사 보안 프로그램(백신, 실행 통제)이 처음 보는 exe를 막거나 지울 수 있습니다. 서명하지 않은 개인 빌드이기 때문입니다. 막히면 우회하지 말고 보안 담당에 이 폴더의 실행 허용을 요청합니다.
- exe도 앱 리뷰와 날씨를 받으려면 외부 접속을 씁니다. 막혀 있으면 `config.local.toml`에서 `app_id = ""`로 리뷰를 끕니다.
- exe 판에는 Claude 요약이 빠져 있어 `allow_llm`을 켜도 문장 틀 요약을 씁니다.
- 빌드 결과(`dist/`, `build/`)는 저장소에 올리지 않습니다. 코드를 고치면 다시 빌드합니다.

### 2. 양식과 내 설정 만들기

```bash
.venv\Scripts\python -m brief.init
```

두 가지가 생깁니다. 있는 파일은 덮지 않습니다.

- `config.local.toml`: 내 설정. `mode = "real"`, 점포 이름, Claude 요약 꺼짐이 들어 있습니다.
- `inputs/` 아래 엑셀 양식 5개. 각 파일의 "설명" 시트에 열마다 적는 법이 있습니다.

### 3. 엑셀 채우기

첫 시트("입력")만 읽습니다. 양식의 열 이름 그대로 붙여 넣는 것이 가장 쉽습니다. CSV(`sales.csv` 등)도 읽습니다.

| 파일 | 꼭 필요한 열 | 있으면 쓰는 열 | 한 줄은 |
|---|---|---|---|
| `sales.xlsx` | 날짜, 구분, 매출 | 목표, 전년 | 하루 한 구분(식품, 패션잡화 등). "전체" 줄이 없으면 구분을 더해 만듭니다 |
| `promotions.xlsx` | 행사명, 시작일, 종료일 | 장소, 매출 구분, 알릴 길, VMD 상태, 담당, 메모 | 행사 하나. "매출 구분"에 sales의 구분(예: 식품)을 적으면 행사 성과를 그 구분 매출로 봅니다. 비우면 전체 매출 |
| `field_log.xlsx` | 날짜, 접점 | 결과, 메모 | 다녀온 접점 하나. 결과가 "문제"나 "해결 중"이면 다음 날 목록 맨 앞에 옵니다 |
| `pilot_weekly.xlsx` | 주차, 그룹, 회원수, 방문 횟수 | 수신 거부 | 한 주 한 그룹("받음" 또는 "남겨둠") |
| `touchpoint_daily.xlsx` | 날짜, 접점, 지표, 값 | 메모 | 하루 한 지표. 예: 문화센터, 수강 신청, 42 / 우수고객 라운지, 이용 수, 310 / 고객 상담실, 문의 주차, 25 |

- 날짜는 `2026-11-04`, `2026.11.04`, 엑셀 날짜 모두 됩니다. 금액은 원 단위 숫자로 적습니다. `1,000,000원`처럼 쉼표와 "원"이 붙어 있어도 읽지만 `100만`은 읽지 못합니다.
- CSV는 엑셀 기본 "CSV(쉼표로 분리)"와 "CSV UTF-8" 둘 다 읽습니다.
- 현장 기록의 접점 이름이 설정에 없으면 그 줄만 건너뛰고 현장 블록 아래에 몇 행인지 적습니다.
- 없는 파일의 블록은 건너뛰고, 화면에 "파일을 넣으면 나옵니다"라고 적습니다. 매출 파일 하나로 시작해도 됩니다.
- 잘못 적은 칸이 있으면 화면 맨 위에 "sales.xlsx 3행 '매출'" 처럼 파일과 행, 열을 적고 그 블록만 비웁니다.
- 매출은 오늘 날짜 줄을 빼고 가장 최근 날(어제 마감)을 봅니다.
- 열 이름 줄 위에 보고서 제목 같은 줄이 있어도 10줄 안이면 찾아 읽습니다. 첫 칸이 "합계", "소계", "총계", "계"인 줄은 건너뜁니다.

#### 사내 파일 열 이름이 다를 때

사내 시스템에서 내려받은 표의 열 이름을 고치지 않고 그대로 넣으려면 `config.local.toml`에 열 이름을 짝지어 적습니다. 왼쪽이 양식 열 이름, 오른쪽이 내 파일 열 이름입니다. 여러 개를 적으면 있는 것을 씁니다.

```toml
[columns.sales]
"날짜" = ["매출일자", "일자"]
"매출" = "순매출"

[columns.promotions]
"행사명" = "프로모션명"
```

열이 없으면 오류 문장에 어느 설정에 적으면 되는지 함께 나옵니다.

### 4. 실행

```bash
scripts\run_brief.bat
```

`output/site/index.html`이 브라우저에 열립니다. 같은 폴더의 `brief.md`는 메신저나 메일에 붙여 넣기 좋은 짧은 글이고, `weekly.md`는 지난 7일 주간 보고 초안, `consult.md`는 담당자별 협의 메모 초안입니다. 실행 기록은 `output/run.log`에 쌓입니다. 탐색기에서 두 번 눌러도 되고, 실패하면 창이 닫히지 않고 이유를 보여 줍니다.
### 5. 매일 아침 자동 실행

Windows 작업 스케줄러에 등록합니다. 아래는 매일 07:30 실행 예시입니다(경로는 내 폴더로 바꿈).

```bash
schtasks /Create /TN "아침 점검" /TR "\"C:\work\dept-morning-brief\scripts\run_brief.bat\" quiet" /SC DAILY /ST 07:30
```

`quiet`를 붙이면 화면을 띄우지 않고 파일만 만듭니다. PC가 꺼져 있으면 돌지 않으니, 출근 직후 `run_brief.bat`를 한 번 눌러도 됩니다.

### 6. 알림(선택)

Slack이나 Teams 수신 웹훅 주소를 환경변수 `BRIEF_WEBHOOK_URL`에 넣으면 "오늘 볼 것 세 가지"를 그 채널로 보냅니다. 주소가 없으면 보내지 않습니다. 알림에는 매출 숫자가 들어가므로 사내 메신저 채널에만 연결합니다.

### 7. 내 점포에 맞게 바꿀 설정

`config.local.toml`에 바꿀 값만 적으면 `config.toml` 위에 덮입니다. 이 파일과 `inputs/`, `output/`은 `.gitignore`에 있어 저장소에 올라가지 않습니다.

| 설정 | 바꿀 것 |
|---|---|
| `[run] store_name` | 화면 머리글의 점포 이름 |
| `[weather] lat, lon` | 내 점포 좌표(비 예보) |
| `[calendar]` 근거 문장, 시간, 혜택 | 기본 문장은 여의도 점포 시연용입니다. 내 점포 집계로 바꿉니다 |
| `[calendar] extra_holidays` | 정기 휴점일, 점포 행사일 |
| `[sales]` 기준 | 전년 대비 경보 %, 목표 달성 경보 % |
| `[promotions]` 기준 | 며칠 앞까지 볼지, VMD 협의가 시작 며칠 전까지 끝나야 하는지, 완료로 보는 단어, 행사 성과를 끝난 뒤 며칠까지 볼지(`result_days`), 성과 경보 %(`result_low_pct`) |
| `[touchpoint_daily]` | 평소와 몇 % 다르면 표시할지(`change_pct`), 너무 작은 숫자는 % 판단에서 뺄 기준(`min_value`) |
| `[columns.파일이름]` | 사내 파일 열 이름 짝짓기 |
| `[consult]` | 협의 초안을 받는 사람 호칭(`vmd`, `channel`, `app`) |
| `[pilot]` | 시범 시작일, 기간, 점검 주차, 본전 비율 |
| `[field] touchpoints` | 접점 이름, 방문 주기(일), 볼 것 질문 |
| `[reviews] app_id` | 볼 앱. 리뷰를 안 볼 때는 `""` |

설정을 고친 뒤에는 `run_brief.bat`를 한 번 눌러 봅니다. 설정이 틀리면 화면이 열리지 않고 창에 "설정 오류: config.local.toml 형식 오류(29행)"처럼 이유가 나오며, 같은 내용이 `output/run.log` 맨 아래에 남습니다.

## 새 항목 반영하기

### 새 자료: 엑셀에 줄을 더합니다

새 행사, 새 매출 구분(예: "뷰티"), 새 현장 기록은 해당 엑셀에 줄만 더하면 다음 실행부터 화면에 나옵니다. 코드와 설정은 그대로 둡니다.

### 새 기준이나 접점: `config.local.toml`에 적습니다

숫자 기준은 바꿀 값만 적습니다.

```toml
[sales]
yoy_alert_pct = -5

[promotions]
vmd_ready_days = 5
done_words = ["완료", "확정", "설치 완료", "검수 완료"]

[calendar]
extra_holidays = { "2026-11-16" = "정기 휴점" }
```

목록(`touchpoints` 같은 `[ ]` 값)은 통째로 바뀝니다. 접점을 하나 더할 때는 `config.toml`의 `[field] touchpoints` 목록 전체를 복사해 붙이고 새 줄을 더합니다. `weekday_place` 같은 상황별 접점과 `review_words`에 적힌 접점 이름이 이 목록에 없으면 실행 때 "점검 질문이 없는 접점" 오류가 납니다.

```toml
[field]
touchpoints = [
  # config.toml 의 기존 줄을 그대로 붙여 넣고
  { name = "VIP 주차장", every_days = 7, check = "발렛 대기 안내와 우수고객 전용 구역 표시가 보이는가" },
]
```

`field_log.xlsx`의 "접점" 열에는 여기 적은 이름을 그대로 씁니다.

### 새 블록: 코드를 더합니다

화면에 없는 업무(예: 사은품 소진 현황)는 세 곳을 더합니다. 문화센터, 라운지, 상담실처럼 "날짜, 접점, 지표, 값"으로 셀 수 있는 숫자는 코드 없이 `touchpoint_daily.xlsx`에 줄만 더하면 됩니다.

1. `brief/inputs.py`의 `SCHEMAS`와 `HELP`에 새 파일 이름과 열을 적습니다. `python -m brief.init`이 양식을 만들어 줍니다.
2. `brief/judge.py`에 판단 함수를 하나 더하고 `brief/main.py`에서 부릅니다. 기준 숫자는 `config.toml`에 둡니다.
3. `docs/index.html`에 블록을 더합니다. sample 모드로 보려면 `brief/samples.py`에 가상 자료도 더합니다.

기존 매출 규칙(`rule_sales`), 행사 규칙(`rule_promos`), 접점 숫자 규칙(`rule_touch`)이 같은 모양이라 그대로 따라 만들면 됩니다.

### 보안 주의

- `config.local.toml`의 `allow_llm`은 꺼 둡니다. 켜면 판단 결과(매출 숫자 포함)가 Claude API로 나갑니다. 꺼져 있으면 정해진 문장 틀로 요약하고, 외부로 나가는 요청은 앱 리뷰와 날씨 조회뿐이며 내 숫자는 들어가지 않습니다.
- `output/` 화면은 내부 자료입니다. GitHub Pages나 공유 폴더에 올리지 않습니다.
- 회사 PC에서 Python 실행과 외부 접속(Google Play, Open-Meteo)이 허용되는지 먼저 확인합니다. 막혀 있으면 `app_id = ""`로 리뷰를 끄면 날씨 조회만 남습니다.

## 판단 규칙

| 규칙 | 판단 |
|---|---|
| 매출 현황 | 어제 또는 최근 7일 전년 대비가 -10% 이하이거나 어제 목표 달성이 90% 미만이면 확인 필요. 구분별로 같은 기준을 따로 봄 |
| 프로모션 점검 | 시작 D-3까지 VMD 상태가 완료, 확정, 설치 완료가 아니면 경고. 알릴 길이 비면 경고. 내일 끝나는 행사는 마감 안내 확인 |
| 행사 성과 | 시작했고 끝난 지 14일 안인 행사. 시작일부터 어제(또는 종료일)까지 매출을 바로 앞 같은 요일 기간(7일 단위로 당김)과 견줌. 0% 이하이면 확인 필요(가정값). 그 구분 매출이 빈 날이 있으면 견주지 않음 |
| 접점 숫자 | 지표마다 최근 값을 직전 4주 같은 요일 평균과 견줌. 30% 이상 늘거나 줄면 확인 필요(가정값). 평균이 5 미만이거나 같은 요일 기록이 2주 미만이면 % 판단을 하지 않음. 현장 점검 접점이면 현장 목록에도 올림 |
| 주간 정리 | 판단을 새로 하지 않고 지난 7일 결과를 모음. 매출 7일 합과 목표, 전년 대비, 행사 성과, 다음 7일 시작 행사, 현장 기록, 접점 숫자 7일 합 |
| 협의 초안 | 판단을 새로 하지 않고 확인 필요 항목을 받는 사람별로 묶음. VMD 경고는 VMD 담당, 알릴 길 미정과 마감 안내는 채널 담당, 성과가 낮은 행사는 둘 다, 구분 매출 경고는 그 구분 영업 담당, 접점 숫자 표시는 그 접점 담당, 리뷰 확인 필요는 앱 운영 담당. 요청 문장은 정해진 목록에서만 고르고, 원인은 단정하지 않음 |
| 4.1 고객 접점 알림 | 1~2점 리뷰를 단어 규칙으로 나눔. 혜택 단어와 로그인 또는 실행 오류 단어가 함께 나오면 막힘. 막힘 1건 이상이거나 새 1~2점이 지난 4주 하루 평균의 2배를 넘으면 확인 필요 |
| 4.2 이번 주 집객 달력 | 평일, 토요일, 일요일과 공휴일, 비 오는 휴일(낮 10~20시 강수 3mm 이상)에 따라 시범, 알릴 길, 보낼 시간, 혜택 유형을 고름 |
| 4.3 시범 점검 | 방문 차이가 유의하고 새 방문 비율이 본전을 넘으면 넓힌다, 본전 아래면 고쳐서 다시, 차이가 없거나 수신 거부가 늘면 멈춘다. 4주차와 10주차는 점검일. 주별 집계 파일이면 방문 수 분산은 포아송 가정 |
| 4.4 오늘 현장 점검 목록 | 막힘 리뷰에 나온 접점, 기록상 "문제"나 "해결 중"인 접점, 숫자가 평소와 다른 접점, 오늘 상황에 맞는 접점, 방문 주기를 넘긴 접점 순으로 최대 3곳. 질문은 설정의 고정 목록에서만 고름 |

기준 숫자는 모두 `config.toml`에 있고 화면의 각 블록 아래에 규칙 문장으로 다시 적힙니다.

## 구조

| 단계 | 하는 일 | 파일 |
|---|---|---|
| 설정 | `config.toml` 위에 `config.local.toml`을 덮음 | `brief/rules_config.py` |
| 입력 | 엑셀과 CSV 읽기, 열 이름 짝짓기, 열과 칸 검사 | `brief/inputs.py`, 양식은 `brief/init.py` |
| 수집 | 앱 리뷰, 7일 예보, 공휴일 | `brief/collect.py` |
| 판단 | 규칙 8개, 주간 정리, 협의 초안 | `brief/judge.py` |
| 작성 | 오늘 볼 것 세 가지, 3문장 요약, 화면 데이터, 주간 정리와 협의 초안 글 | `brief/write.py`, `docs/index.html` |
| 알림 | 웹훅으로 세 가지 보내기 | `brief/notify.py` |
| exe | Python 없는 PC용 묶음 | `scripts/build_exe.bat`, `scripts/exe_entry.py` |

| 모드 | 입력 | 결과 |
|---|---|---|
| `sample`(기본, 공개 시연) | `brief/samples.py`가 만든 가상 파일 | `docs/`, `data/`(GitHub Pages) |
| `real`(내 업무) | `inputs/`의 내 파일 | `output/site/`, `output/data/`(내 PC) |

## 지키는 것

- 리뷰 원문, 작성자 이름, 리뷰 ID는 출력과 저장소에 남기지 않습니다. 원문은 실행 중 분류에만 쓰고 버리며, 저장 직전에 원문이 파일에 들어갔는지 검사합니다. 들어갔으면 저장하지 않습니다.
- 공개 시연에는 현대백화점 내부 매출, 회원, 행사 자료를 쓰지 않습니다. 시연 숫자는 모두 가상입니다.
- 푸시나 메시지를 고객에게 보내지 않고, 매출을 예측하지 않습니다. 정해 둔 기준과 비교해 볼 곳을 알려 줄 뿐입니다.
- 한 단계가 실패하면 화면에 실패한 단계와 이유, 마지막 성공 날짜를 적고 나머지 블록은 그대로 만듭니다.

## 한계

- 사내 시스템에 직접 붙지 않습니다. 매출, 행사, 시범, 현장 기록, 접점 숫자는 사용자가 엑셀로 내려받아 넣어야 합니다.
- 행사 성과는 앞 기간과의 단순 비교입니다. 다른 행사, 날씨, 시즌 영향을 빼지 않았으므로 행사 효과로 단정하지 않습니다.
- exe는 서명하지 않은 개인 빌드라 회사 보안 정책에 따라 실행이 막힐 수 있습니다.
- 알릴 길(앱 푸시, 문자나 메신저 알림, 매장 안내물, 문화센터 공지)은 후보이며 실제 운영 채널인지는 확인하지 않았습니다.
- 달력의 기본 근거 문장은 포트폴리오에서 낸 여의도역 집계(서울교통공사 OA-12921, 공공누리 3유형)입니다. 원자료는 이 저장소에 없고, 다른 점포에서는 설정에서 바꿔야 합니다.
