# 백화점 마케팅 아침 점검 에이전트

매일 아침 7시(KST)에 공개 데이터와 가상 데이터를 모아 브리핑 한 장을 만듭니다.

- 화면: https://jhheo51-arch.github.io/dept-morning-brief/
- 오늘 브리핑 Markdown: [docs/brief.md](docs/brief.md)

브리핑은 세 가지를 담습니다.

1. 고객 접점에서 생긴 불편(앱 리뷰)
2. 이번 주에 사람을 모을 때와 알릴 길(날씨 예보, 요일, 공휴일)
3. 진행 중인 시범의 판단 신호(가상 데이터)

여기에 그날 돌아볼 현장 접점 목록을 붙입니다. 가 본 결과를 쓰는 도구가 아니라, 갈 곳과 볼 것을 정해 주는 도구입니다.

## 구조

| 단계 | 하는 일 | 파일 |
|---|---|---|
| 수집 | 앱 리뷰, 7일 예보, 공휴일, 가상 시범 데이터 | `brief/collect.py` |
| 판단 | 규칙 4개. 모든 판단에 근거 숫자와 규칙 이름을 붙임 | `brief/judge.py`, `brief/rules_config.py` |
| 작성 | 오늘 볼 것 세 가지, 3문장 요약, 화면 데이터 | `brief/write.py`, `docs/index.html` |
| 기록 | 날짜별 집계 JSON만 쌓음 | `data/history/`, `data/latest.json` |

판단은 규칙으로 합니다. 숫자와 기준을 따라가며 확인할 수 있게 하기 위해서입니다. 문장 다듬기만 Claude(`claude-sonnet-5-5`)에 맡길 수 있습니다. `ANTHROPIC_API_KEY`가 있을 때만 쓰고, 요약에 나온 숫자가 판단 JSON에 없으면 요약을 버리고 정해진 문장 틀로 씁니다.

## 규칙 4개

| 규칙 | 데이터 | 판단 |
|---|---|---|
| 4.1 고객 접점 알림 | 현대백화점 앱(`com.ehyundai.mcard`) Google Play 공개 리뷰 | 1~2점 리뷰를 포트폴리오 5쪽과 같은 단어 규칙으로 나눔. 혜택 단어와 로그인 또는 실행 오류 단어가 함께 나오면 막힘. 막힘 1건 이상이거나 새 1~2점이 지난 4주 하루 평균의 2배를 넘으면 확인 필요 |
| 4.2 이번 주 집객 달력 | Open-Meteo 7일 예보(여의도, CC BY 4.0), 공휴일(인사혁신처) | 평일은 17~20시 퇴근길(승차 16,483명), 일요일은 토요일보다 하차 29% 적음, 비 온 휴일은 여의도역 하차 1.02배(실내 행사 후보). 비는 낮(10~20시) 강수 3mm 이상 |
| 4.3 시범 점검(가상) | 가상 회원 2만 명(SEED 2026), 시범 시작일 2026-10-12(가정값) | 포트폴리오 7쪽 기준. 방문 차이가 유의하고 새 방문 비율이 본전 25%(가정값)를 넘으면 넓힌다, 본전 아래면 고쳐서 다시, 차이가 없거나 수신 거부가 늘면 멈춘다. 4주차와 10주차는 점검일 |
| 4.4 오늘 현장 점검 목록 | 4.1과 4.2 결과 | 지난 7일 막힘 리뷰에 나온 접점과 오늘 상황에 맞는 접점, 최대 3곳. 점검 질문은 코드의 고정 목록에서만 고름 |

4.2의 하차, 승차 숫자는 포트폴리오에서 낸 집계 상수입니다. 서울교통공사 OA-12921(공공누리 3유형, 변경금지) 원자료는 이 저장소에 없습니다. 알릴 길(앱 푸시, 문자나 메신저 알림, 매장 안내물, 문화센터 공지)은 후보이며 실제 운영 채널인지는 확인하지 않았습니다.

## 지키는 것

- 리뷰 원문, 작성자 이름, 리뷰 ID는 출력과 저장소에 남기지 않습니다. 원문은 실행 중 분류에만 쓰고 버리며, 저장 직전에 원문이 파일에 들어갔는지 검사합니다. 들어갔으면 커밋하지 않습니다.
- 현대백화점 내부 매출, 회원, 행사 자료는 쓰지 않습니다. 시범 수치는 모두 가상 데이터입니다.
- 푸시나 메시지를 실제로 보내지 않고, 매출을 예측하지 않습니다.
- 한 단계가 실패하면 화면에 실패한 단계와 마지막 성공 날짜를 적고, 그 블록은 마지막 성공 결과로 채웁니다.

## 실행

```bash
pip install -r requirements.txt
python -m brief.main            # 오늘 브리핑
python -m brief.main --date 2026-11-09   # 실행일을 바꿔 보기
python -m pytest -q             # 테스트
LIVE_REVIEWS=1 python -m pytest -q   # 실제 리뷰와 대조해 저장소에 원문이 없는지 검사
```

GitHub Actions(`.github/workflows/daily.yml`)가 매일 07:00 KST(cron `0 22 * * *`)에 테스트, 브리핑, 원문 검사를 차례로 돌리고 `docs/`와 `data/`를 커밋합니다.
