# 백화점 마케팅 아침 점검 에이전트

출근 전에 혼자 돌아서, 마케팅 담당자가 아침에 확인할 것을 한 장으로 모아 줍니다. 판단은 정해진 규칙으로 하고, 모든 판단에 근거 숫자와 규칙 문장을 붙입니다.

- 시연 화면: https://jhheo51-arch.github.io/dept-morning-brief/
- 시연 화면의 매출, 행사, 시범, 현장 기록은 모두 가상 데이터입니다. 앱 리뷰와 날씨, 공휴일만 공개 자료입니다.

## 마케터가 먼저 읽을 부분

- 아침에 하던 확인(매출, 행사 준비, 리뷰, 날씨)을 출근 전에 한 장으로 받아 봅니다. 그 시간을 기획과 현장에 씁니다.
- 이번 주 날짜마다 누구에게, 무엇을, 어느 길로, 어떤 문구로 알릴지 기획 초안을 만들어 줍니다. 초안은 재료일 뿐이고 정하는 것은 담당자입니다.
- 오늘 협의할 일을 VMD, 채널, 영업, 앱 운영 담당별 메모로 묶어 줍니다. 메시지는 사람이 보냅니다.
- 실제 자료로 확인한 것: 현대백화점 앱 Google Play 리뷰 1년치로 리뷰 알림 규칙을 매일 돌려 보니 338일 중 20일 알림이 떴습니다(주 0.41일). 매출, 행사, 시범 숫자는 가상이라 실제 효과는 아직 모릅니다.
- 회사 PC에서는 인터넷에 나가지 않는 설정(`offline = true`)으로 내 엑셀만 읽게 할 수 있습니다. 내 숫자는 밖으로 나가지 않습니다.

## 내 업무에 적용하기

회사 PC(Windows)에서 내 엑셀로 돌리는 방법입니다. 내 자료는 내 PC 안에서만 읽고 씁니다. Python을 설치할 수 없는 PC라면 아래 "Python 없이 쓰기(exe)"를 먼저 봅니다.

### 1. 설치

```bash
git clone https://github.com/jhheo51-arch/dept-morning-brief.git
```

```bash
cd dept-morning-brief
```

```bash
python -m venv .venv
```

```bash
.venv\Scripts\pip install -r requirements-run.txt
```

Python 3.11 이상이 필요합니다. `requirements-run.txt`에는 꼭 필요한 세 가지(numpy, holidays, openpyxl)만 있습니다. 앱 리뷰나 Claude 요약까지 쓰거나 테스트를 돌릴 때만 `requirements.txt`를 씁니다. 회사 PC에 설치가 막혀 있으면 IT 담당에 먼저 확인하거나 아래 두 방법 가운데 하나를 씁니다.

### 인터넷이 막힌 PC에 설치하기

인터넷이 되는 PC에서 설치 파일을 받아 USB나 사내 공유 폴더로 옮깁니다. 두 PC의 Python 버전(예: 3.12)과 Windows 64비트가 같아야 합니다.

인터넷이 되는 PC에서:

```bash
pip download -r requirements-run.txt -d wheels
```

`wheels` 폴더와 저장소 폴더를 회사 PC로 옮긴 뒤 회사 PC에서:

```bash
.venv\Scripts\pip install --no-index --find-links wheels -r requirements-run.txt
```

회사 PC는 `config.local.toml`의 `offline = true`(양식을 처음 만들 때 기본값)를 그대로 둡니다. 날씨와 앱 리뷰를 받지 않고, 화면도 외부 글꼴 대신 PC 글꼴을 씁니다.

### Python 없이 쓰기(exe)

Python이 있는 PC에서 한 번 만들고, 만든 폴더를 회사 PC로 옮겨 씁니다.

```bash
scripts\build_exe.bat
```

`dist\morning_brief` 폴더가 생깁니다. 이 폴더를 통째로 회사 PC의 원하는 곳(예: `C:\work\morning_brief`)에 복사합니다. 폴더 안의 `run_brief.bat`를 두 번 누르면 처음에는 `inputs\` 양식과 `config.local.toml`을 만들고 멈춥니다. 엑셀을 채운 뒤 다시 누르면 `output\site\index.html`이 열립니다. 아래 3번부터는 같고, `run_brief.bat`도 이 폴더의 것을 씁니다.

- 회사 보안 프로그램(백신, 실행 통제)이 처음 보는 exe를 막거나 지울 수 있습니다. 서명하지 않은 개인 빌드이기 때문입니다. 막히면 우회하지 말고 보안 담당에 이 폴더의 실행 허용을 요청합니다.
- exe도 앱 리뷰와 날씨를 받으려면 외부 접속을 씁니다. 처음 만든 `config.local.toml`은 `offline = true`라 외부에 접속하지 않습니다. 회사 IT에서 접속을 허용받은 뒤에만 false 로 바꿉니다.
- exe 판에는 Claude 요약이 빠져 있어 `allow_llm`을 켜도 문장 틀 요약을 씁니다.
- 빌드 결과(`dist/`, `build/`)는 저장소에 올리지 않습니다. 코드를 고치면 다시 빌드합니다.

### 2. 양식과 내 설정 만들기

```bash
.venv\Scripts\python -m brief.init
```

두 가지가 생깁니다. 있는 파일은 덮지 않습니다.

- `config.local.toml`: 내 설정. `mode = "real"`, 점포 이름, Claude 요약 꺼짐이 들어 있습니다.
- `inputs/` 아래 엑셀 양식 6개(sales, promotions, tasks, field_log, pilot_weekly, touchpoint_daily). 각 파일의 "설명" 시트에 열마다 적는 법이 있습니다.

### 3. 엑셀 채우기

첫 시트("입력")만 읽습니다. 양식의 열 이름 그대로 붙여 넣는 것이 가장 쉽습니다. CSV(`sales.csv` 등)도 읽습니다.

| 파일 | 꼭 필요한 열 | 있으면 쓰는 열 | 한 줄은 |
|---|---|---|---|
| `sales.xlsx` | 날짜, 구분, 매출 | 목표, 전년 | 하루 한 구분(식품, 패션잡화 등). "전체" 줄이 없으면 구분을 더해 만듭니다 |
| `promotions.xlsx` | 행사명, 시작일, 종료일 | 장소, 매출 구분, 목표, 알릴 길, VMD 상태, 담당, 메모 | 행사 하나. "매출 구분"에 sales의 구분(예: 식품)을 적으면 행사 성과를 그 구분 매출로 봅니다. 비우면 전체 매출. "목표"는 행사 기간 전체의 그 구분 매출 목표(원, `30억`이나 열 이름 `목표(천원)`도 됨) |
| `tasks.xlsx` | 업무 | 기한, 상태, 담당, 관련 행사, 완료일, 메모 | 업무 하나. 기한은 `11/07`처럼 연도를 빼도 되고, 비우면 "기한 없음"으로 맨 뒤에 둡니다. 상태에 "완료"(또는 끝, 취소)를 적으면 다음 실행부터 보관 목록으로 옮깁니다. "관련 행사"에 행사명을 적고 업무 이름에 VMD, 알릴 길(채널, 푸시, 문자), 마감 안내 같은 말이 있으면 그 행사 경고와 잇습니다 |
| `field_log.xlsx` | 날짜, 접점 | 결과, 메모 | 다녀온 접점 하나. 결과가 "문제"나 "해결 중"이면 다음 날 목록 맨 앞에 옵니다 |
| `pilot_weekly.xlsx` | 주차, 그룹, 회원수, 방문 횟수 | 수신 거부 | 한 주 한 그룹("받음" 또는 "남겨둠") |
| `touchpoint_daily.xlsx` | 날짜, 접점, 지표, 값 | 메모 | 하루 한 지표. 예: 문화센터, 수강 신청, 42 / 우수고객 라운지, 이용 수, 310 / 고객 상담실, 문의 주차, 25 |

- 날짜는 `2026-11-04`, `2026.11.04`, `26.11.04`, `20261104`, `2026년 11월 4일`, `11/04(수)`, 엑셀 날짜 모두 됩니다.
- 금액은 기본이 원 단위입니다. 사내 표가 천원 단위면 열 이름의 `매출(천원)`처럼 단위를 그대로 두거나, 설정 `[sales] unit = "천원"`으로 정합니다. 칸에 `300만원`, `1.2억`, `350만`처럼 단위가 붙어 있으면 그 단위를 따릅니다. `(1,200)`과 `△1,200`은 음수, `-`만 적힌 칸은 빈 칸으로 읽습니다. 매출 블록 출처 줄에 어떤 단위로 읽었는지 적습니다.
- 행사 기간은 시작일과 종료일 두 칸 대신 `기간` 한 칸(`11/7~11/10`, `2026.11.07 - 2026.11.10`, `11월 7일부터 10일까지`)도 됩니다.
- CSV는 엑셀 기본 "CSV(쉼표로 분리)"와 "CSV UTF-8" 둘 다 읽습니다.
- 현장 기록의 접점 이름이 설정에 없으면 그 줄만 건너뛰고 현장 블록 아래에 몇 행인지 적습니다.
- 없는 파일의 블록은 건너뛰고, 화면에 "파일을 넣으면 나옵니다"라고 적습니다. 매출 파일 하나로 시작해도 됩니다.
- 잘못 적은 칸이 있으면 화면 맨 위에 "sales.xlsx 3행 '매출'" 처럼 파일과 행, 열을 적고 그 블록만 비웁니다.
- 매출은 오늘 날짜 줄을 빼고 가장 최근 날(어제 마감)을 봅니다.
- 열 이름 줄 위에 보고서 제목 같은 줄이 있어도 10줄 안이면 찾아 읽습니다. 첫 칸이나 구분 같은 필수 열 칸이 "합계", "소계", "총계", "누계"로 끝나는 줄은 건너뜁니다. 병합 셀로 내려받아 날짜 칸이 비어 있으면 윗줄 날짜를 이어 씁니다.
- 머리글만 있고 자료가 없는 파일은 "없는 파일"과 따로 "내용이 빈 파일"로 알려 줍니다.

#### 사내 파일 열 이름이 다를 때

사내 시스템에서 내려받은 표의 열 이름을 고치지 않고 그대로 넣으려면 `config.local.toml`에 열 이름을 짝지어 적습니다. 왼쪽이 양식 열 이름, 오른쪽이 내 파일 열 이름입니다. 여러 개를 적으면 있는 것을 씁니다.

```toml
[columns.sales]
"날짜" = ["매출일자", "일자"]
"매출" = "순매출"

[columns.promotions]
"행사명" = "프로모션명"
```

열이 없으면 오류 문장에 어느 설정에 적으면 되는지 함께 나옵니다.

#### 사내 BI가 파일을 날마다 떨어뜨릴 때

사내 BI나 공유 폴더에 예약 내보내기가 있으면 붙여 넣지 않아도 됩니다. `config.local.toml`의 `[sources]`에 파일 이름마다 경로 패턴을 적으면 `inputs/` 대신 그 패턴에 맞는 xlsx, csv 중 가장 최근 파일을 읽습니다. 엑셀이 열어 둔 임시 파일(`~$`)은 건너뜁니다.

```toml
[sources]
sales = "D:/BI_export/일매출_*.xlsx"
touchpoint_daily = "%USERPROFILE%/Downloads/접점일보_*.csv"
```

읽은 파일과 바뀐 시각은 오늘 탭 오늘 할 일 아래 "읽은 파일"에 나옵니다. 그 파일이 오늘 전에 바뀌었으면(내보내기가 안 돈 날) 화면 맨 위와 `brief.md`에 "오늘 전에 바뀐 파일"로 알립니다. 열 이름이 양식과 다르면 위 `[columns]`와 함께 씁니다. 사내 BI가 그런 내보내기를 주는지는 확인하지 않았습니다.

### 4. 실행

```bash
scripts\run_brief.bat
```

`output/site/index.html`이 브라우저에 열립니다. 같은 폴더의 `brief.md`는 메신저나 메일에 붙여 넣기 좋은 짧은 글이고, `weekly.md`는 지난 7일 주간 보고 초안, `consult.md`는 담당자별 협의 메모 초안, `lead.md`는 팀장 보고 한 장입니다. 실행 기록은 `output/run.log`에 쌓입니다. 탐색기에서 두 번 눌러도 되고, 실패하면 창이 닫히지 않고 이유를 보여 줍니다.
### 5. 매일 아침 자동 실행

Windows 작업 스케줄러에 등록합니다. 아래는 매일 07:30 실행 예시입니다(경로는 내 폴더로 바꿈).

```bash

```

`quiet`를 붙이면 화면을 띄우지 않고 파일만 만듭니다. PC가 꺼져 있으면 돌지 않으니, 출근 직후 `run_brief.bat`를 한 번 눌러도 됩니다.

### 6. 알림(선택)

Slack이나 Teams 수신 웹훅 주소를 환경변수 `BRIEF_WEBHOOK_URL`에 넣으면 "오늘 볼 것 세 가지"를 그 채널로 보냅니다. 주소가 없거나 `offline = true`이면 보내지 않습니다. 알림에는 매출 숫자가 들어가므로 사내 메신저 채널에만 연결합니다.

### 7. 내 점포에 맞게 바꿀 설정

`config.local.toml`에 바꿀 값만 적으면 `config.toml` 위에 덮입니다. 이 파일과 `inputs/`, `output/`은 `.gitignore`에 있어 저장소에 올라가지 않습니다.

| 설정 | 바꿀 것 |
|---|---|
| `[run] store_name` | 화면 머리글의 점포 이름 |
| `[weather] lat, lon` | 내 점포 좌표(비 예보) |
| `[calendar]` 근거 문장, 시간, 혜택 | 기본 문장은 여의도 점포 시연용입니다. 내 점포 집계로 바꿉니다 |
| `[calendar] extra_holidays` | 정기 휴점일, 점포 행사일 |
| `[sales]` 기준 | 전년 대비 경보 %, 목표 달성 경보 %, 덜 된 집계로 볼 기준. 사내 BI 마감 시각(`confirm_hour`)을 적으면 매출 파일을 그 시각 전에 받았는지로 가리고, 적지 않으면 어제 매출이 최근 같은 요일 평균의 `partial_pct`(가정값 80) % 미만인지로 가립니다. 해당하면 구분별 경고를 멈추고 파일을 다시 받으라고 알립니다. 매출 단위가 원이 아니면 화면과 brief.md에 단위를 적습니다 |
| `[promotions]` 기준 | 며칠 앞까지 볼지, VMD 협의가 시작 며칠 전까지 끝나야 하는지, 완료로 보는 단어, 행사 성과를 끝난 뒤 며칠까지 볼지(`result_days`), 성과 경보 %(`result_low_pct`), 목표 대비 경보 %(`target_low_pct`), 시작 며칠째부터 예상으로 알릴지(`target_min_days`) |
| `[tasks]` | 보관으로 옮길 상태 단어(`done_words`), 며칠 남았을 때부터 앞에 표시할지(`soon_days`), 화면에 보일 업무 수(`max_rows`), 보관 목록을 며칠 남길지(`archive_days`), 내 업무로 볼 담당 이름(`me`). 다른 담당이 맡은 기한 임박 업무는 협의 초안에 들어갑니다. 완료한 업무를 보관할 때 이름이 같고 기한 차이가 7일 미만인 보관 항목은 기한만 고친 같은 업무로 보고 하나로 합칩니다. 매주 하는 업무는 따로 남습니다 |
| `[weekly]` | 주간 정리 끝 '다음 주 점검'에 붙일 요일별 반복 점검(`checks`, "요일: 할 일" 꼴). 예시 값이니 팀 일정으로 바꿉니다 |
| `[touchpoint_daily]` | 평소와 몇 % 다르면 표시할지(`change_pct`), 너무 작은 숫자는 % 판단에서 뺄 기준(`min_value`) |
| `[columns.파일이름]` | 사내 파일 열 이름 짝짓기 |
| `[run] offline` | `true`이면 인터넷에 나가지 않음(리뷰와 날씨를 건너뛰고 요일과 공휴일로만 달력을 만듦) |
| `[consult]` | 협의 초안을 받는 사람 호칭(`vmd`, `channel`, `app`), 메모를 직접 보낼 사람(`direct`, 기본은 VMD와 채널 담당). 나머지는 팀장 보고로 넘깁니다 |
| `[plan]`, `[plan.1]`~`[plan.3]` | 기획 초안 카드 수, 시범별 대상, 문구 A와 B(비 문구 `copy_a_rain`), 재는 법, 맡을 곳 |
| `[pilot]` | 시범 시작일, 기간, 점검 주차, 본전 비율 |
| `[field] touchpoints` | 접점 이름, 방문 주기(일), 볼 것 질문 |
| `[reviews] app_id` | 볼 앱. 리뷰를 안 볼 때는 `""` |

설정을 고친 뒤에는 `run_brief.bat`를 한 번 눌러 봅니다. 설정이 틀리면 화면이 열리지 않고 창에 "설정 오류: config.local.toml 형식 오류(29행)"처럼 이유가 나오며, 같은 내용이 `output/run.log` 맨 아래에 남습니다.

## 화면 쓰는 법

화면은 탭 다섯 개로 나뉩니다. 탭 옆 숫자는 그 탭에서 확인이 필요한 건수입니다. 마지막에 본 탭은 다음에 열 때 그대로 열립니다.

| 탭 | 들어 있는 것 |
|---|---|
| 오늘 | 오늘 볼 것 세 가지, 한눈에 보기 칸, 팀장 보고 한 장, 오늘 할 일과 판단 기록, 현장 점검 |
| 숫자 | 어제 매출, 접점 숫자, 앱 리뷰, 지난 판단 기록 |
| 행사와 업무 | 진행 행사, 내 업무, 이번 주 집객 달력 |
| 협의와 기획 | 담당자별 협의 메모, 기획 초안, 시범 판단 |
| 주간 보고 | 주간 정리와 다음 주 점검 |

- 한눈에 보기 칸과 "오늘 볼 것" 문장을 누르면 그 내용이 있는 블록으로 옮겨 갑니다. 주황 칸이 확인할 곳입니다.
- 오늘 할 일은 오늘 볼 것, 지났거나 오늘까지인 업무, 현장 점검, 보낼 협의 메모를 한 목록으로 모읍니다. 체크 표시는 그 PC 브라우저에만 날짜별로 남고 엑셀은 바뀌지 않습니다. 끝난 업무는 `tasks.xlsx`에 "완료"로 적습니다.
- 팀장 보고 한 장은 오늘 탭 둘째 칸입니다. "보고 글 복사"를 눌러 메신저나 메일에 붙여 넣고, 숫자와 담당만 한 번 더 본 뒤 보냅니다. 원인은 같은 구분의 최근 7일과 같은 구분 행사만 후보로 적고, 전년 같은 날의 행사와 날씨처럼 이 도구에 없는 것은 그 구분 영업 담당에게 묻는다고 씁니다.
- 오늘 할 일의 "확인" 줄 옆 "움직였다", "볼 필요 없었다" 단추로 알림마다 판단을 남깁니다. 기록은 그 PC 브라우저에 날짜별로 쌓이고, 아래에 움직인 비율이 나옵니다. "판단 기록 CSV 받기"로 날짜, 항목, 판단을 내려받아 4주 시범 통과 기준을 셉니다.
- 복사 단추: 팀장 보고 글, 아침 공유 글(제목, 세 가지, 요약), 협의 메모, 기획 문구 A와 B, 주간 정리 전체를 눌러서 바로 메신저나 메일에 붙여 넣을 수 있습니다.
- 주소 끝에 `#plan`처럼 탭 이름(today, numbers, work, plan, week)을 붙이면 그 탭으로 열립니다. 담당자에게 특정 탭 링크를 보낼 때 씁니다.
- 각 블록의 판단 기준과 출처는 "+ 판단 기준과 출처"를 눌러야 펼쳐집니다.
- 인쇄 단추를 누르면 탭과 단추를 빼고 모든 탭 내용을 한 번에 인쇄합니다.

## 새 항목 반영하기

### 새 자료: 엑셀에 줄을 더합니다

새 행사, 새 매출 구분(예: "뷰티"), 새 현장 기록은 해당 엑셀에 줄만 더하면 다음 실행부터 화면에 나옵니다. 코드와 설정은 그대로 둡니다.

### 새 기준이나 접점: `config.local.toml`에 적습니다

숫자 기준은 바꿀 값만 적습니다.

```toml
[sales]
yoy_alert_pct = -5

[promotions]
vmd_ready_days = 5
done_words = ["완료", "확정", "설치 완료", "검수 완료"]

[calendar]
extra_holidays = { "2026-11-16" = "정기 휴점" }
```

완료 단어 앞뒤에 "미", "아직", "예정", "대기", "전", "중" 같은 말이 붙으면 끝나지 않은 것으로 봅니다. `미완료`, `완료 예정(11/6)`, `확정 대기`는 경고가 남고, `완료(10/30)`, `설치완료`는 완료로 봅니다.

목록(`touchpoints` 같은 `[ ]` 값)은 통째로 바뀝니다. 접점을 하나 더할 때는 `config.toml`의 `[field] touchpoints` 목록 전체를 복사해 붙이고 새 줄을 더합니다. `weekday_place` 같은 상황별 접점과 `review_words`에 적힌 접점 이름이 이 목록에 없으면 실행 때 "점검 질문이 없는 접점" 오류가 납니다.

```toml
[field]
touchpoints = [
  # config.toml 의 기존 줄을 그대로 붙여 넣고
  { name = "VIP 주차장", every_days = 7, check = "발렛 대기 안내와 우수고객 전용 구역 표시가 보이는가" },
]
```

`field_log.xlsx`의 "접점" 열에는 여기 적은 이름을 그대로 씁니다.

### 새 블록: 코드를 더합니다

화면에 없는 업무(예: 사은품 소진 현황)는 세 곳을 더합니다. 문화센터, 라운지, 상담실처럼 "날짜, 접점, 지표, 값"으로 셀 수 있는 숫자는 코드 없이 `touchpoint_daily.xlsx`에 줄만 더하면 됩니다.

1. `brief/inputs.py`의 `SCHEMAS`와 `HELP`에 새 파일 이름과 열을 적습니다. `python -m brief.init`이 양식을 만들어 줍니다.
2. `brief/judge.py`에 판단 함수를 하나 더하고 `brief/main.py`에서 부릅니다. 기준 숫자는 `config.toml`에 둡니다.
3. `docs/index.html`에 블록을 더합니다. sample 모드로 보려면 `brief/samples.py`에 가상 자료도 더합니다.

기존 매출 규칙(`rule_sales`), 행사 규칙(`rule_promos`), 접점 숫자 규칙(`rule_touch`)이 같은 모양이라 그대로 따라 만들면 됩니다.

### 보안 주의

- `config.local.toml`의 `allow_llm`은 꺼 둡니다. 켜면 판단 결과(매출 숫자 포함)가 Claude API로 나갑니다. 꺼져 있으면 정해진 문장 틀로 요약하고, 외부로 나가는 요청은 앱 리뷰와 날씨 조회뿐이며 내 숫자는 들어가지 않습니다.
- `output/` 화면은 내부 자료입니다. GitHub Pages나 공유 폴더에 올리지 않습니다.
- 회사 PC에서 Python 실행과 외부 접속(Google Play, Open-Meteo)이 허용되는지 먼저 확인합니다. IT 승인 전이거나 외부 접속이 막혀 있으면 `config.local.toml`의 `[run]`에 `offline = true`를 적습니다. 리뷰, 날씨, Claude 요약을 모두 건너뛰고 인터넷에 전혀 나가지 않습니다. 달력은 요일과 공휴일로만 만들고, 나머지 블록은 그대로 나옵니다.
- exe는 서명하지 않은 개인 빌드입니다. 회사 PC에서 쓰기 전에 IT 담당에 보여 주고 허용을 받습니다. 어려우면 Python 판을 쓰거나, 승인 전까지는 집 PC에서 가상 자료로만 돌려 봅니다.

| 규칙 | 판단 |
|---|---|
| 매출 현황 | 세 단계. 어제 또는 최근 7일 전체 전년 대비가 -10% 이하이거나 어제 전체 목표 달성이 90% 미만이면 확인 필요. 전체는 기준 안이고 구분 하나라도 같은 기준을 넘으면 구분 확인. 둘 다 아니면 평소. 오늘 탭, 요약 문장, 숫자 탭, 30일 기록, 알림이 모두 같은 값을 씀 |
| 프로모션 점검 | VMD 상태에 "완료"나 "확정"이 들어 있으면 끝난 것으로 봄(`완료(10/30)`도 됨). 시작 D-3까지 끝나지 않았으면 경고. "요청 전"이면 7일 안의 행사는 바로 경고. 알릴 길이 비면 경고. 내일 끝나는 행사는 마감 안내 확인 |
| 행사 성과 | 시작했고 끝난 지 14일 안인 행사. 시작일부터 어제(또는 종료일)까지 매출을 바로 앞 같은 요일 기간(7일 단위로 당김)과 견줌. -5% 이하이면 확인 필요(가정값). 그 구분 매출이 빈 날이 있으면 견주지 않음. 행사 파일에 목표가 있으면 목표 대비도 봄. 진행 중이면 예상 = 지금까지 매출 + 남은 날의 앞 같은 요일 매출 x (지금까지 매출 / 지금까지 날의 앞 같은 요일 매출)이고, 시작 3일째부터 예상이 목표의 95% 미만이면 확인 필요(가정값). 끝난 행사는 실제 달성률로 봄. 매출은 행사만의 매출이 아니라 그 구분 전체 매출 |
| 접점 숫자 | 지표마다 최근 값을 직전 4주 같은 요일 평균과 견줌. 30% 이상 늘거나 줄면 확인 필요(가정값). 평균이 5 미만이거나 같은 요일 기록이 2주 미만이면 % 판단을 하지 않음. 현장 점검 접점이면 현장 목록에도 올림 |
| 주간 정리 | 판단을 새로 하지 않고 지난 7일 결과를 모음. 매출 7일 합과 목표, 전년 대비, 행사 성과, 다음 7일 시작 행사, 현장 기록, 접점 숫자 7일 합. 다음 주 점검: 7일 안 기한 업무, 시작 전 경고 남은 행사, 지난주 끝난 행사 결과 보고, 덜 된 매출 파일, 설정의 요일별 점검 |
| 협의 초안 | 판단을 새로 하지 않고 확인 필요 항목을 받는 사람별로 묶음. VMD 경고는 VMD 담당, 알릴 길 미정과 마감 안내는 채널 담당, 성과가 낮은 행사는 둘 다, 구분 매출 경고는 그 구분 영업 담당, 접점 숫자 표시는 그 접점 담당, 리뷰 확인 필요는 앱 운영 담당. 같은 사람에게 가는 같은 행사 항목은 한 줄로 묶음. 요청 문장은 정해진 목록에서만 고르고, 원인은 단정하지 않음 |
| 4.1 고객 접점 알림 | 1~2점 리뷰를 단어 규칙으로 나눔. 혜택 단어와 로그인 또는 실행 오류 단어가 함께 나오면 막힘. 막힘 1건 이상이거나 새 1~2점이 지난 4주 하루 평균의 2배를 넘으면 확인 필요 |
| 4.2 이번 주 집객 달력 | 평일, 토요일, 일요일과 공휴일, 비 오는 휴일(낮 10~20시 강수 3mm 이상)에 따라 시범, 알릴 길, 보낼 시간, 혜택 유형을 고름. "마지막 날" 문구는 행사 파일에서 그날 끝나는 행사가 있을 때만 그 이름으로 쓰고, 없으면 다른 문장을 씀. 화면에는 오늘, 주말과 공휴일, 비 오는 날, 행사가 끝나는 날만 먼저 보이고 나머지 평일은 접어 둠 |
| 4.3 시범 점검 | 방문 차이가 유의하고 새 방문 비율이 본전을 넘으면 넓힌다, 본전 아래면 고쳐서 다시, 차이가 없거나 수신 거부가 늘면 멈춘다. 4주차와 10주차는 점검일. 주별 집계 파일이면 방문 수 분산은 포아송 가정 |
| 기획 초안 | 판단을 새로 하지 않고 이번 주 달력에서 시범별로 가장 가까운 날을 골라 설정의 대상, 문구, 재는 법을 채움. 그날 비 예보가 있으면 비 문구를 씀. 진행 중인 시범 판단과 성과가 낮았던 행사를 참고 줄로 붙임. 혜택 문장은 설정값이라, 그날 걸친 행사 파일 항목(이름 첫 낱말이 혜택 문장에 있는 것)이 없으면 문구 앞에 "[혜택 확정 후]"를 붙임. 최대 3장 |
| 팀장 보고 한 장 | 판단을 새로 하지 않음. 결론은 매출 세 단계와 덜 된 집계 여부로 고름. 구분 확인이면 기준을 넘은 구분 중 전년 대비가 가장 낮은 것을 앞에 둠. 원인 후보는 그 구분의 최근 7일 전년 대비(7일이 다 있을 때만), 7일 안에 끝났거나 진행 중인 같은 구분 행사 성과뿐이고 원인으로 단정하지 않음. 조치는 구분 영업 담당, 기한이 지났거나 오늘인 업무, 업무로 안 잡힌 행사 경고, 접점 숫자, 리뷰 순으로 4개까지. 정해 주실 것은 시범 점검일과 진행 중인데 성과가 낮은 행사(목표 대비 예상이 낮으면 그 숫자와 남은 날) |
| 4.4 오늘 현장 점검 목록 | 막힘 리뷰에 나온 접점, 기록상 "문제"나 "해결 중"인 접점, 숫자가 평소와 다른 접점, 오늘 상황에 맞는 접점, 방문 주기를 넘긴 접점 순으로 최대 3곳. 질문은 설정의 고정 목록에서만 고름 |

기준 숫자는 모두 `config.toml`에 있고 화면의 각 블록 아래에 규칙 문장으로 다시 적힙니다.

## 실제 자료로 검증한 것

리뷰 알림 규칙(4.1)을 현대백화점 앱의 Google Play 공개 리뷰로 지난 1년 매일 7시에 돌렸다고 보고 다시 계산했습니다. 앞 28일은 기준 기간이라 판단하지 않았습니다.

| 항목 | 결과 |
|---|---|
| 기간 | 2025-11-30 ~ 2026-11-02, 338일 |
| 확인 필요가 뜬 날 | 20일(주 0.41일) |
| 그중 막힘 리뷰 때문 | 5일 |
| 1~2점 리뷰가 온 날 | 모두 알림이 뜸 |

이 앱은 1~2점 리뷰가 드물어 4주 평균이 0에 가깝고, 그래서 "평균의 2배" 기준은 사실상 1건만 와도 알림이 됩니다. 알림이 주 1회도 안 되어 아침에 보기 부담은 없지만, 리뷰가 많은 앱이라면 기준 배수를 다시 정해야 합니다. 원문, 작성자, 리뷰 ID는 저장하지 않고 날짜별 건수만 남깁니다.

```bash
python -X utf8 scripts/backtest_reviews.py
```

적중률은 아직 셀 수 없습니다. 이 20일 알림이 맞았는지는 "그날 누군가 움직여야 했는가"를 사람이 정해야 하는데, 원문을 저장하지 않아 나중에 되짚을 수도 없습니다. 그래서 적중률은 아래 4주 시범에서 날마다 적고, `scripts/trial_report.py`가 판단 기록 중 리뷰 항목만 떼어 셉니다.

시간도 아직 재지 못한 부분이 있습니다. 이 PC에서 시연 자료로 한 번 돌리는 데 걸린 시간은 세 번 재어 2.3~2.5초입니다. 사람이 엑셀을 내려받아 넣는 시간과 화면을 읽고 팀장에게 보고하기까지 걸리는 시간은 실제 업무에서만 잴 수 있어 시범 기준에 넣었습니다.

매출, 행사, 시범 규칙은 가상 자료로만 돌렸습니다.

### 4주 시범 통과 기준

실제로 쓴다면 첫 4주는 날마다 한 줄씩 적습니다. 화면이 낸 확인 필요 항목마다 오늘 할 일의 "움직였다", "볼 필요 없었다" 단추를 누르고(4주 뒤 CSV로 받음), 내가 따로 찾았는데 화면에 없던 일을 적고, 엑셀 넣는 데 걸린 분과 출근부터 팀장 보고까지 걸린 분을 적습니다. 시범 전 1주도 같은 방식으로 보고 시간을 적어 둡니다. 아래 숫자는 모두 가정값이고, 4주 뒤 팀장과 함께 다시 정합니다.

| 기준 | 통과 |
|---|---|
| 확인 필요 항목 중 실제로 움직인 비율 | 50% 이상 |
| 화면이 놓친 일(내가 따로 찾은 일) | 주 1건 이하 |
| 출근부터 팀장 보고까지 | 시범 전 1주 평균보다 10분 이상 줄어듦 |
| 엑셀 내려받아 넣는 시간 | 하루 10분 이하 |
| 읽기 실패 | 주 1회 이하 |

다섯 가지를 모두 넘으면 계속 쓰고, 하나라도 못 넘으면 그 이유를 적어 기준이나 블록을 고친 뒤 4주를 다시 봅니다. 셋 이상 못 넘으면 그만 씁니다.

오늘 탭 오늘 할 일 아래 "아침 점검 시작"과 "팀장 보고 마침"을 누르면 그 사이 분을 날짜별로 세고, "엑셀 넣은 분"에 입력 시간을 적으면 함께 남습니다. "시간 기록 CSV 받기"로 4주치를 받아 위 두 시간 기준을 셉니다. 기록은 그 PC 브라우저에만 남습니다. 시범 전 1주는 이 도구 없이 같은 화면만 열어 두 단추를 눌러 잽니다.

화면이 놓친 일은 `missed.csv`에 `날짜,놓친 일` 두 칸으로 직접 적습니다. 4주 뒤 아래 명령이 다섯 가지 기준을 한 번에 셉니다. 읽기 실패는 기록 폴더의 날짜별 실행 기록에서 셉니다. 기준 숫자는 `config.toml`의 `[trial]`에 있고, 기록이 3일보다 적은 기준은 "셀 자료 없음"으로 두고 판정하지 않습니다. 리뷰 알림이 맞았는지는 판단 기록 중 리뷰 항목만 떼어 함께 적습니다.

```bash
python -X utf8 scripts/trial_report.py --start 2026-11-09 --judge judge_log.csv --time time_log.csv --missed missed.csv --out trial_report.md
```

### 사내 BI가 있을 때 최소 구성

어제 매출, 목표 달성, 전년 대비, 구분별 표는 점포에 사내 BI나 일일 매출 속보가 있으면 이미 매일 아침 봅니다. 그럴 때 이 도구의 매출 블록은 같은 숫자를 다시 보여 줄 뿐이라 새 가치가 거의 없습니다. 겹치지 않는 것은 행사 준비 상태(VMD, 알릴 길, 마감 안내), 업무 기한, 현장 점검, 접점 숫자를 한 장에 묶는 부분입니다.

| 구성 | 넣는 파일 | 나오는 것 | 빠지는 것 |
|---|---|---|---|
| 최소(BI와 겹치지 않게) | `promotions`, `tasks`, `field_log` | 행사 준비 경고, 업무 기한, 현장 점검, 협의 메모, 기획 초안 | 매출 블록, 행사 성과, 팀장 보고의 매출 숫자 |
| 최소 + 행사 성과 | 위 셋 + `sales`(`[sources]`로 BI 내보내기를 바로 읽음) | 위 + 행사 목표 대비와 남은 날 예상, 매출 구분 경고 | 없음. 붙여 넣는 일은 없지만 BI 화면과 숫자가 겹침 |
| 전체 | 여섯 파일 모두 | 모두 | 없음 |

최소 구성으로 시작해 4주 시범을 보고, 행사 성과를 목표 대비로 보는 일이 손으로 자주 되풀이되면 그때 `sales`를 BI 폴더로 붙입니다. 매출을 손으로 붙여 넣는 구성은 입력 시간이 하루 10분 기준을 넘기 쉬워 권하지 않습니다.

### 블록 끄기 규칙

블록은 입력 폴더에서 그 엑셀 파일을 빼면 꺼집니다. 리뷰 블록은 `offline = true`나 앱 ID를 비우면 꺼집니다.

- 2주 동안 알림이 한 번도 실제 행동으로 이어지지 않은 블록은 기준을 고치거나 끕니다.
- 알림이 주 3일 넘게 뜨는데 움직인 비율이 30% 아래인 블록은 기준을 한 단계 올립니다.
- 리뷰 블록은 4주 동안 1~2점 1건 알림이 행동으로 이어진 적이 없으면 막힘 리뷰만 알리도록 바꿉니다.

## 지키는 것

- 리뷰 원문, 작성자 이름, 리뷰 ID는 출력과 저장소에 남기지 않습니다. 원문은 실행 중 분류에만 쓰고 버리며, 저장 직전에 원문이 파일에 들어갔는지 검사합니다. 들어갔으면 저장하지 않습니다.
- 공개 시연에는 현대백화점 내부 매출, 회원, 행사 자료를 쓰지 않습니다. 시연 숫자는 모두 가상입니다.
- 푸시나 메시지를 고객에게 보내지 않고, 매출을 예측하지 않습니다. 정해 둔 기준과 비교해 볼 곳을 알려 줄 뿐입니다.
- 한 단계가 실패하면 화면에 실패한 단계와 이유, 마지막 성공 날짜를 적고 나머지 블록은 그대로 만듭니다.

## 운영과 인수인계

아직 운영 주체를 정하지 않았습니다. 아래는 한 점포 한 팀에서 시범을 한다고 보고 정한 제안이고, 실제로는 팀장과 IT 담당이 함께 정합니다.

### 누가 무엇을 맡나(제안)

| 일 | 맡는 사람 | 필요한 것 |
|---|---|---|
| 매일 실행 확인, 엑셀 넣기, 판단 기록과 시간 기록 | 행사 담당 마케터 1명, 부담당 1명 | 화면 쓰는 법만 |
| 기준값, 담당 이름, 사내 열 이름, BI 경로 바꾸기 | 같은 마케터 | `config.local.toml`에서 예시 줄을 복사해 값만 고치기 |
| 설치, 작업 스케줄러, BI 예약 내보내기, 회사 PC 보안 승인 | IT나 BI 담당 | 처음 한 번과 PC를 바꿀 때 |
| 규칙이나 블록을 새로 만들기, 오류 코드 고치기 | Python을 읽을 수 있는 사람(데이터팀이나 IT) | 아래 세 파일과 `python -m pytest -q` |

### 만든 사람이 없을 때 볼 세 파일

1. `config.local.toml`: 기준 숫자, 담당 이름, 사내 열 이름, BI 경로가 모두 여기 있습니다. 고칠 것의 대부분은 이 파일에서 끝납니다. 설정 이름은 "7. 내 점포에 맞게 바꿀 설정"에 있습니다.
2. `output/run.log`: 날마다 어느 단계가 실패했는지, 어느 파일 몇 행 무슨 열이 문제인지 적힙니다. 화면 맨 위 실패 안내와 같은 문장입니다.
3. `brief/judge.py`: 블록마다 `rule_` 로 시작하는 함수 하나가 판단을 맡습니다(`rule_sales`, `rule_promos`, `rule_tasks`, `rule_promo_results`, `rule_touch` 등). 고친 뒤에는 `tests/`의 테스트를 돌려 다른 블록이 깨지지 않았는지 봅니다.

### 멈추면 무엇을 보나

이 도구는 입력 엑셀을 읽기만 하고 고치지 않습니다. 멈춰도 예전 방식으로 바로 돌아갈 수 있습니다.

| 증상 | 그날 할 일 | 고치는 법 |
|---|---|---|
| 화면 맨 위에 "실패"가 뜸 | 그 블록은 마지막 성공 결과이므로 그 숫자는 쓰지 않고, 매출은 사내 BI 화면, 행사와 업무는 원래 엑셀을 봅니다 | 실패 문장의 행과 열을 엑셀에서 고치거나, 열 이름이 바뀌었으면 `[columns.파일이름]`에 적습니다 |
| "오늘 전에 바뀐 파일"이 뜸 | 그 파일로 만든 블록은 어제 자료일 수 있어 BI 화면을 봅니다 | BI 담당에게 예약 내보내기가 돌았는지 묻습니다 |
| 07:30에 화면이 안 만들어짐 | `scripts
un_brief.bat`를 눌러 직접 돌립니다. 그래도 안 되면 예전 방식으로 보고합니다 | 작업 스케줄러 "아침 점검" 작업과 `output/run.log`를 IT 담당과 봅니다 |
| exe나 Python이 회사 보안에 막힘 | 예전 방식으로 보고합니다 | IT 승인 전까지 쓰지 않습니다 |

### 언제 끄나

- 4주 시범 통과 기준 다섯 가지 중 셋 이상을 못 넘을 때(위 "4주 시범 통과 기준").
- 담당자가 바뀌었는데 2주 안에 새 담당이 위 세 파일 중 `config.local.toml`과 `output/run.log`를 다루지 못할 때.
- 회사 보안이나 개인정보 점검에서 쓰지 말라는 답을 받았을 때.

끌 때는 작업 스케줄러에서 "아침 점검" 작업을 지우고(`schtasks /Delete /TN "아침 점검"`), 폴더는 4주 판단 기록과 시간 기록 CSV만 남기고 지웁니다. 입력 엑셀은 원래 자리에 그대로 있습니다.

### 넘겨줄 때 30분 점검

새 담당이 직접 해 봅니다. 넷 다 되면 넘깁니다.

1. `python -m brief.main --date 2026-11-03`으로 시연 화면을 만들고 오늘 탭을 읽어 봅니다.
2. `config.local.toml`에서 기준값 하나(예: `yoy_alert_pct`)를 바꾸고 다시 돌려 화면 규칙 문장이 바뀐 것을 봅니다.
3. 사내 엑셀 열 이름 하나를 `[columns]`에 짝지어 읽혀 봅니다.
4. 일부러 날짜 칸 하나를 지운 파일을 넣고, 화면 실패 안내와 `output/run.log`에서 그 행을 찾아 고칩니다.

## 한계

- 사내 시스템에 직접 붙지 않습니다. `[sources]`로 BI 폴더의 파일을 읽을 수는 있지만, 그 폴더에 파일을 날마다 떨어뜨리는 예약 내보내기가 있어야 하고 이것은 IT나 BI 담당과 정해야 합니다. 실제 도입은 이 경로가 있어야 한다고 봅니다. 없으면 엑셀로 내려받아 넣어야 합니다.
- 줄어드는 시간은 아직 재지 않았습니다. 시간 기록 단추와 `scripts/trial_report.py`는 재고 세는 도구일 뿐이고, 시범 전과 시범 중 숫자는 없습니다. 4주 통과 기준 다섯 가지도 모두 가정값이며, 스크립트는 기록이 모자라면 판정하지 않습니다.
- 덜 된 집계 판단은 사내 BI 마감 시각을 모르면 같은 요일 평균의 80% 미만인지로 가립니다(가정값). 이 기준은 실제 하락이 20%를 넘는 날도 파일 탓으로 볼 수 있어, 실제로 쓰면 `confirm_hour`를 적어 받은 시각으로 가리는 쪽을 권합니다.
- 행사 성과는 앞 기간과의 단순 비교입니다. 다른 행사, 날씨, 시즌 영향을 빼지 않았으므로 행사 효과로 단정하지 않습니다.
- 행사 목표 대비는 그 구분 전체 매출로 잽니다. 행사 상품만의 매출이나 행사 코드별 매출은 이 도구에 없으므로, 목표도 같은 기준(그 구분의 행사 기간 매출)으로 적어야 맞습니다. 예상은 남은 날도 지금까지와 같은 배율로 간다고 본 값이라 주말 날씨나 마지막 날 몰림은 반영하지 않습니다.
- exe는 서명하지 않은 개인 빌드라 회사 보안 정책에 따라 실행이 막힐 수 있습니다.
- 실제 자료로 검증한 것은 리뷰 알림 규칙 하나입니다. 1~2점이 드문 앱이라 2배 기준은 1건 알림으로 동작합니다. 매출, 행사, 시범 판단 기준은 가정값이며 실제 효과는 확인하지 않았습니다.
- 기획 초안의 대상, 문구, 재는 법은 설정 문장을 고르는 것이지 새로 만들지 않습니다. 쓸 만한 문구인지는 담당자가 판단합니다.
- 알릴 길(앱 푸시, 문자나 메신저 알림, 매장 안내물, 문화센터 공지)은 후보이며 실제 운영 채널인지는 확인하지 않았습니다.
- 달력의 기본 근거 문장은 포트폴리오에서 낸 여의도역 집계(서울교통공사 OA-12921, 공공누리 3유형)입니다. 원자료는 이 저장소에 없고, 다른 점포에서는 설정에서 바꿔야 합니다.
